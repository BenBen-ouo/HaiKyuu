# AI 進攻與防守能力

本文件記錄目前能力拉條的遊戲行為，修改難度時一併更新。數值的實際來源為 `model/ai/AiTuning.java`，反應曲線為 `AiDifficulty.java`；本文件不取代程式設定。

進攻、防守各有五個刻度：入門、簡單、普通、困難、專家，分別映射到既有代表值 20／40／60／80／100，預設皆為普通（60）。進場後固定；整場重開保留難度並清空習慣統計。內部沿用原本連續換算公式與隨機抽樣，不重寫五套 AI。以下的 21／41／61 等數值是保留的內部解鎖門檻，不是選單額外可選的刻度。

## 進攻拉條

| 項目 | 從哪裡開始有差異 | 各區段實際變化 |
| --- | --- | --- |
| 發球種類 | 1 即有普通／低網，2 起可能短發／天花板球 | 後兩種的條件抽樣機率隨進攻提高；選跳發時不走此分支，不代表所有球種一起等比例增加 |
| 跳發 | 普通，41 起 | 入門、簡單不使用；解鎖後機率逐點提高。依接觸位置選擇可用的現有跳發變化 |
| 快攻配球／MB 第二球 | 簡單，21 起 | 入門不使用；簡單起隨能力增加快配使用率。Setter 接第一球後，若現有貼網球路可達，也會評估 MB 直接打第二球，不依賴 Setter 再次配球，不固定優先 MB |
| Setter 跳舉 | 普通，41 起 | 簡單以下不使用；解鎖後逐點提高嘗試機率，還須實際可接觸到球 |
| 負節奏 | 簡單，21 起 | 入門不使用；解鎖後逐點提高。站舉時以 Setter 接觸前約 42～48 幀開始 WS 助跑／後排起跳，球路不允許則改其他節奏 |
| 第一／第二節奏 | 基本能力 | MB 第一節奏須已解鎖快攻配球；WS／後排第二節奏在出球頂點附近開始動作。時機擾動限於目前演算法設定，不改角色速度 |
| WS／後排混合節奏 | 多人組織，41 起 | 當本次有負節奏且參與上限大於一人，80% 的方案會把其中一人改為第二節奏，兩種角色分配皆可出現；保留少量雙負節奏。能否實際完成仍受球路、起跳及本次可用人數限制 |
| 後排攻擊準備位置 | 所有難度 | 攻擊與假起跳都先移到三米線附近的合法後場側。準備帶依目前跳躍速度、重力、橫速、攻擊框及球半徑計算，讓最高點的攻擊框前緣可觸及 Setter 圖片中心橫向位置；再逐幀確認實際來球是否可打。趕不上就不跳，不以深後場原地假跳代替。空中舉球不套用此準備帶 |
| 進攻人數 | 41 起雙人，61 起三人 | 入門、簡單單人；普通可能雙人；困難以上可能三人。實際扣球者須有可達窗口；WS／後排可在合法位置真實假跑起跳，MB 不為不可達球路空跳。已起跳者持續占用名額 |
| 主動假扣真舉／二次攻擊 | 困難，61 起 | 第一球接起後，只要 WS／後排有合法空中第二球窗口，就抽一次舉球或二次扣球偏好；不再限於 Setter 接第一球。排除上一位觸球者，保留正常 Setter 組織。Setter 第一球後原有的直接攻擊／空中舉球救援另計；60 以下禁止空中舉球，沒有新增 Setter 主動二次扣球 |
| 空檔判斷 | 普通，41 起 | 1～40 優先選擇朝向現有防守者、較容易接起的可行球路，保留變化；41 起比較對手防守空隙與攔網 |
| 攔網回彈選路 | 困難，61 起 | 出手時估計可見 MB 的攔網交會與回彈；雙負節奏且無人來得及補救時，更避開封死路線。WS／後排若能在回彈前落地並移動到接球窗口，即使剛假跑也算補救者；可救回後場或三米內的路線加分，不強迫故意打攔網 |
| 球路選擇 | 基本扣球從 1，吊球從 21 | 入門不吊球；簡單以上可能短吊、長吊。MB 正常扣球可用時，吊球候選機率額外降低；只有吊球可用時仍可選吊球 |
| 組織反應 | 1～100 連續改善 | 進攻開始的等待、發球決策使用進攻反應曲線，與防守拉條分開 |

進攻評估遵守現有角色、球速與碰撞規則，不因高難度放大框或增加跳躍力；規劃窗口有時無法實際完成，仍可失誤。

## 防守拉條

| 項目 | 從哪裡開始有差異 | 各區段實際變化 |
| --- | --- | --- |
| 反應速度 | 1～100 連續改善 | 通常由 0.4 秒改善至 0.2 秒，高能力偶爾 0.15 秒；陌生來回球路另加辨識延遲，猜錯／反彈後重新判讀也需等待，不停止物理與動畫 |
| 接球位置誤差 | 1～100 連續改善 | 全難度硬上限 ±60px；入門較常大誤差，專家較常在 ±20px 內，但仍可能大誤判。每次判讀抽一次，同一飛行追蹤期間不重抽 |
| 跑步／撲救 | 所有難度都有 | 共用可達窗口判斷，考慮跑步加速及撲球減速；能力透過反應與估計誤差影響結果，沒有另一套專家物理 |
| WS／後排分工 | 所有難度都有 | WS 可站接時不撲；否則找最晚可啟動的滑行接球窗口。窗口有效時後排留在後場，失效才補接；彈網後重新判讀。對手仍有可見攻擊窗口的配球不直接當成短吊球追接 |
| 後排退防 | 所有難度都有 | 本隊扣球已向對場飛行時就開始回防，不等對手接起第一球；對手組織時維持三米至九米預備區。習慣資料依能力影響深淺站位，實際追球不受預備區限制 |
| 本隊進攻時提前補位 | 普通，41 起 | 入門、簡單不做；後排沒有攻擊／假跑／第三球支援任務時，才可能從底線附近提前前進至後場中央。每次本隊第一球後抽樣一次，之後不每幀重抽 |
| 攻擊者預判 | 1～100 連續改善 | 低能力較偏隨機，高能力更重視可見助跑／起跳及習慣；不讀對手未公開輸入 |
| 節奏預判 | 簡單，21 起 | 入門固定預判第二節奏，快球與近網估計不能把它提前改成快攻時機；簡單起結合猜測、公開動作及習慣預判 |
| 攔網時機 | 1～100 連續改善 | 對手接起第一球後至少觀察到球通過最高點，才決定第一次攔網；對手殘留的 BLOCK 動作不當成新進攻。時機誤差逐點縮小，入門另保留第二節奏等待；因此最高點前的快速進攻可能攔不到 |
| 積極修正攔網 | 困難，61 起 | 已通過最高點與反應等待後，檢查所有可見攻擊者未來 22 幀的攻擊框交會；即使原先猜錯，只要 MB 仍在地面且有機會，就提前修正舊起跳期限。仍受角色高度、已使用攔網接觸及正常落地限制 |
| 補攔 | 普通，41 起 | 簡單以下同一對手組織只允許首次攔網起跳；普通起可落地後再判斷。次數取自 MB 實際狀態，不因重新預測重置；若已使用攔網接觸，仍遵守原本接觸限制 |
| 進階戰術辨識 | 困難，61 起 | 依已發生的空中舉球、Setter 跳舉與多人準備重新分工；等防守反應延遲後才抽一次辨識，困難 60%、專家 85%。辨識成功時清除過時的攔網時限及接球分工，重新檢查可達攻擊者與公開起跳節奏；仍可能受騙，不取消角色動作，也不跳過首次攔網最高點限制 |
| 對手習慣 | 所有難度都記錄 | 攻擊落點按攻擊者及節奏分開記錄；高能力更重視習慣。反覆快速深球還會影響後排進攻／假跑安排，避免落地後來不及回防。樣本先驗避免單次觀察支配決策，整場重開清空 |

發球與攻擊的落地位置分開累計；攻擊再依後排／MB／WS、負一／第一／第二節奏分類。只記已觀察到出手、未被本隊接觸或撞網中斷的首次實際落地，得分後反彈不重複記錄；被成功接起的球不產生落地樣本。無法確認舉球與起跳先後時，不視為快速節奏。

反覆的負一／第一節奏深球會累積回防風險。樣本足夠且依防守能力加權後達門檻時，每次本隊組織最多 45% 的戰術抽樣會檢查後排起跳、落地及跑回習慣落點的時間；有其他可行攻擊者才保留來不及回防的後排，不再每次都排除其參戰。後排是唯一可用攻擊點或負責空中舉球救援時仍保留機會。這是保守估計，不讀取對手下一球決策，也不保證接起。既有多人進攻與戰術解鎖門檻維持不變。

對手最後觸球、球體已離開界線且持續朝場外飛行，估計落地也在界外時，不再追救。白線與球半徑沿用正式判定；只是停止追球，不提前給分。自己最後觸球或球仍向場內飛時不套用。

## 五階段代表值與既有公式

以下是五個可選階段代入原公式後的數值，不是成功率。反應時間另有約 ±8% 隨機差異，最後換算為整個遊戲 tick；同一階段仍會抽到不同誤差及戰術。

| 設定 | 入門 20 | 簡單 40 | 普通 60 | 困難 80 | 專家 100 |
| --- | --- | --- | --- | --- | --- |
| 進攻／防守通常反應時間 | 0.32 秒 | 0.28 秒 | 0.25 秒 | 0.22 秒 | 0.20 秒 |
| 抽到大於 20px 誤差的機率 | 約 62.1% | 48.6% | 35.1% | 21.5% | 8% |
| 攔網時機誤差參數 | 約 ±14.1 幀 | ±9.2 幀 | ±5.8 幀 | ±3.7 幀 | ±3 幀 |

入門攔網把時機誤差取為延後量，再加第二節奏等待，不套用可提前的正負誤差。進攻出手／起跑窗口目前共用 ±2 幀排程擾動，沒有額外以能力改變這個常數。

誤差分兩段抽樣：小誤差在 0～20px 均勻抽，大誤差在 20～60px 均勻抽，再對稱選正負。大誤差機率隨能力線性由 75% 降至 8%，不是每個區段各有一個固定誤差。快速反應為 `12% × ((能力 - 1) / 99)²` 的機會抽到 9 tick（0.15 秒）；其餘使用通常反應曲線與 ±8% 擾動。來回球的陌生球路辨識另外增加最多 6 tick（0.1 秒），依該種已觀察攻擊方向的樣本數逐漸減少；碰網或球速突變後重新判讀，不沿用先前預估立即改追。

各使用率的公式、上限集中在 AiTuning：

- 快攻配球：21 起，條件機率約由 22% 提高至 50%；必須不是 Setter 自己接第一球。
- 負節奏：21 起由小機率逐點升至 55%；Setter 跳舉：41 起升至 95%。上述是嘗試方案的抽樣，不代表實際完成率。
- 跳發：41 起逐點增加，最高選用機率約 48.75%；正常／低網／短發／天花板分支另計。
- 雙人：41 起，選擇至少兩人的機率為 `(進攻 - 40) / 60`。三人：61 起，在已選多人時再乘 `(進攻 - 60) / 40`。仍須角色可配合。
- 主動假扣真舉偏好：困難 15%、專家 30%；未選中後再抽二次扣球，困難 15%、專家 35%。只在找到合法空中第二球窗口後抽一次，不逐幀或重規劃重抽；窗口消失則回正常組織。若兩種窗口都存在，困難的三種意圖分布為 15% 舉球、12.75% 二次扣球、72.25% 正常組織；專家為 30%、24.5%、45.5%。這是條件意圖分布，不是實際完成率；Setter 第一球後無其他接應的既有救援另計。內部 61～80 使用困難值，80～100 線性銜接專家值。
- 一般吊球候選：21 起，最高約 28%；MB 正常扣球可用時再乘 0.15，最高約 4.2%。候選不保證最後被選中；只有吊球可過網時不套用此機率限制。
- 入門／簡單選路：85% 選擇可用候選中，通過接球高度時最靠近對手後排／WS 的球路；其餘隨機選可行候選。不是 85% 保證接起，也不修改球速或碰撞箱。
- 混合節奏：多人方案已抽到負節奏時，80% 將 WS／後排其中一人改為第二節奏；不是整體對局 80% 都打混合節奏。三人組織可跨不同時間啟動，不要求每名角色都能碰到同一顆配球。
- 高難度回彈評分：61 起，估計回到本隊且無人可救時扣 180 分；雙負節奏時扣分乘 1.5；有人可救則加 50 分。仍與空檔、攔網、吊球偏好及隨機性合併評分，不保證選同一條路線。
- 後排提前補位：41 起，抽樣機率為 `0.9 × (防守 - 40) / 60`，最高 90%；後排已被進攻規劃保留時不執行。
- 快速深球回防：至少 3 個攻擊落地樣本；快速深球比例以 8 個先驗樣本平滑，再乘防守能力的正規化值，達 0.20 才影響後排參戰安排。深球指本方底線至向網前三米，含球半徑的底線邊緣；回防比較使用保守的起步跑速及對方最早 30 幀回擊預算。參數集中在 `AiTuning`，不是新增的階段解鎖或成功率。
- 普通以上的球路選擇會評估空檔；改選隨機可行方案的機率隨進攻提高而下降，最高能力仍保留約 2%。這不是出界／掛網機率。40 以下採上述朝向防守者的偏好，不套用空檔攻擊評分。

回彈估計使用當下公開的攔網框尺寸、旋轉、動畫階段與跳躍速度；反射公式與正式碰撞共用 `BlockReflection`，反彈係數仍讀 `GameConfig`；手部框另共用可調最低反彈速度，頭部圓框不套用下限。手框使用旋轉矩形包絡做保守估計，正式圓角判定不變；不預知對手未來起跳或觸球，也未模擬反彈後再次碰網／碰人。補救估計只考慮 WS 與後排，包含落地等待；WS 遵守回位及朝網撲救限制，不能自由橫移。這些是決策偏好，非必然結果。

## 本場打法紀錄與進攻學習

`GameModel` 在實際接受觸球後產生有序 `ContactEvent`，`AiMatchLearning` 依事件 ID 去重，不靠揮臂圖片猜測出手。一般接球、空中舉球、扣球、攔網與真正發出球分開；拋球不算發球出手。

- `RuleBasedAi.statistics()` 提供不可變查詢結果；目前只存本場記憶體，不新增 UI、檔案或跨場保存。所有難度都記錄，`R` 清空。
- 實際出手按本／對方、角色、第二／第三球與球路分類；發球另有球種。出手情境另記節奏、站舉／跳舉／空中舉球、實際參與準備的人數、對手可見攔網與空檔。二次攻擊沒有可確認的舉球時間時記 UNKNOWN，不冒充第二節奏；Setter 第三球送球記 FREE_BALL，不冒充主動扣球。
- 安排與完成分開：未碰到球只記「安排但未完成」，不計有效出手。空中舉球成功、跳舉與多人準備也有獨立計數。
- 出手結果分為直接得分、被一般接起、攔回後繼續、被攔死、自身失誤與其他。對手一旦一般接起，前次出手即結為被救起；其後反攻失誤不追溯算前次攻擊成功。直接得分另分落地、打手出界、發球直接得分；攔網直接得分及自己 MB 被打出界分別列在攔網結果。
- 落點／實際接球位置分別計數，按距網 0～3、3～6、6～9 米及界外鏡像分區。只有已確認落地才記落點；救起時記接球位置，不拿自由飛行預測充當真實落點。
- 攔網預判記實際起跳次數、攻擊者猜對／節奏猜對的檢核分母與次數、碰球、直接得分、被打出界、繼續比賽，不能只用起跳或碰到球當成功。無法觀察的節奏不加入節奏正確率分母。
- 僅困難／專家的進攻讀取自身成果。每個「攻擊者＋第二／第三球＋球路」至少 7 次實際出手才啟用；以 8 個先驗樣本平滑，單一打法選擇權重為 `1 + 0.25 × 直接得分次數 / (出手次數 + 8)`，上限 1.25。更細情境也須自身累積 7 次，與基礎權重取較大者、不連乘；發球目前只記錄，不套用此攻擊學習。被救起、被攔死與自身失誤都不增加直接得分次數。
- 學習只調整目前可行球路之間的相對選擇權重，不提高球速、碰撞範圍、角色能力或總成功率，也不讓不可用球路變可用。

## 調整與驗證入口

- 參數與解鎖值：`model/ai/AiTuning.java`；標籤與反應曲線：`AiDifficulty.java`。
- 進攻／發球：`OffensePlanner`、`AttackOptions`、`ServePlanner`；防守／補位：`DefensePlanner`。
- `AiPolicyTest`：門檻、空檔選擇、負節奏及補攔；`AiTacticsTest`：實際接球、進攻轉換與提前補位；`AiMatchTest`：完整對局、能力分離與重開。
- `model.ai.AiLearningTest`：情境落點、樣本信心、落地去重與重開、左右對稱的實際進攻安排及接球後遭遇 MB 快攻的連續攻防。
- `model.ai.AiDefenseBalanceTest`：誤差機率分布、反應下限、最高點攔網門檻、WS 站接／延後撲救、實際彈網分工、界外不救與 MB 第二球攻擊。測試使用固定亂數；一般對局的真實成功率仍需人工確認。
- `model.ai.AiTacticalChoiceTest`：入門選路、61 分門檻、攔網重判、實際混合／三人準備、反射方向、假跑落地後的補救能力，以及三種攻擊者會隨補救窗口改變選路。節奏排程案例會暫時不按空中第二次攻擊，以獨立觀察後續準備；正常擊球與完整對局另由 AiTacticsTest／AiMatchTest 驗證。
- `model.ai.AiStatisticsTest`：第二球一次抽樣與兩側實際觸球、非 Setter 第一球的主動組織、事件去重、得分歸因、攔網／發球分類、接球與落地分區、未完成安排、7 次門檻、權重上限及戰術辨識延遲／抽樣。
- 後排準備案例從深後場開始，驗證實際走位、合法起跳及最高點橫向範圍；空中舉球救援沿用 AiTacticsTest 的既有案例。LauncherTest 驗證五個刻度、25 組進攻／防守映射、左右模式與普通預設值。
- 日常及打包測試入口見 [AGENTS.md](../AGENTS.md)。自動案例結果不能當成真人得分率或勝率。
